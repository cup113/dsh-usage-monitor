# dsh-token-quota 侧边栏与设置界面迭代方案

日期：2026-10-03。状态：UI01–UI06 已完成，最终候选包已通过必要验证；未提交、推送或发布。

本方案面向当前仓库 `dsh-token-quota`，借鉴 `dsh-usage` 的侧栏速览、折叠交互和集中展示方式，优化日常查看额度与配置供应商的操作。主要交付为一个可以折叠的侧栏卡片，以及一个共用内容的用量监控面板。实施分为六批，验收集中为五组。

本文是实施规范，原始代码位置对应下述固定基线。实施进度见[简短执行记录](sidebar-settings-execution.md)，最终验收结果记录在本文末尾。

## 基线与取舍

| 对象 | 已核对的基线 | 本方案用途 |
| --- | --- | --- |
| 当前插件 | `v1.4.0`，提交 `a0ec978e14b258842256f14a168c262c5cd8975e` | 确认现有组件、接口、测试和桌面适配边界。 |
| 参考插件 | `zhu1090093659/dsh-web` 的 `dev`，提交 `007e49c7af5565e80c82a384d0f61f7675a42446` | 参考侧栏卡片与设置页的信息组织。 |
| 宿主接口 | DeepSeek Harness 提交 `639ed015397290b3745d163aafe02ffee4aa3f84`；仓库桌面适配基线为 `0.2.0-rc.2` | 确认槽位和设置导航的能力边界。实施时记录实际运行版本。 |

参考插件在侧栏提供可折叠速览，将详细数据集中到设置分区。采用这两点，但按当前插件的“周期限额、余额、报告费用”能力组织内容。参考插件的成本估算、Token 银行和趋势台账不属于本轮范围，不能仅凭界面改动承诺这些能力。

参考插件的 `foot-card-mount.tsx` 使用宿主 DOM 选择器插入卡片，并通过模拟点击进入设置分区。当前插件已经使用 `sidebar.footer.action` 和 `settings.section`，应继续保留这两个官方槽位。

已查阅的宿主契约中，普通 `settings.section` 只接收 `close`；`openSection` 属于 onboarding 的专属接口。因此，本轮默认采用以下可执行路径：侧栏直接打开插件自己的监控对话框，原生设置分区嵌入同一个面板内容。二者共用数据、组件与配置逻辑，不依赖未公开的跳转接口，也不复制参考插件的 DOM 点击逻辑。

## 目标界面

### 侧栏卡片

完整状态保留四行信息。以下数值仅为布局示例。

```text
用量监控                         收起
OpenCode · 模型名称
5 小时已用 63%          2h13m 后重置
今日用量 1.24M tokens
```

主操作区域点击后直接进入监控面板的“概览”。收起按钮与主操作按钮为同级元素，避免嵌套按钮和误触。完整状态目标高度约为 88–104 CSS px，根据宿主字体实际调整。

紧凑状态为一行，优先保留供应商和主指标：

```text
OpenCode · 5 小时已用 63%          展开
```

显示规则如下。

1. 供应商来自当前显示会话最近一次真实调用。没有调用时显示“暂无调用”，不借用其他会话的供应商。
2. 周期限额使用现有“已用百分比”口径，选取已用比例最高的有效窗口；同一行必须显示该窗口名称与对应的重置时间。缺少重置时刻时不生成倒计时。
3. 余额直接显示币种和金额。多币种保持独立，侧栏显示一个余额条目及“另有 N 项”，完整内容放在概览中，不相加、不换算。
4. 报告费用与报告用量保留原有统计周期。不能将组织账单的最近完整 UTC 日写成“今日”，也不能将报告费用写成余额。
5. 今日用量沿用现有 `suppliers.filter(s => s.current)` 后汇总 `todayTokens` 的口径，不变更记账和筛选算法。卡片的可访问说明及概览说明明确写出“当前供应商的今日 Token 用量，按宿主本地日统计”。它不是当前会话用量，也不是全部历史路由的当日总量。
6. 连接状态缩为状态标记，正常时不占主指标位置；失败时显示短文案。沿用现有事件观测口径，不将“已见事件”解释成实时网络在线。
7. 取数失败但有旧数据时，显示“更新失败 · 上次数据”，旧值使用中性色；没有旧数据时显示“暂时无法获取”。未知值用 `—`，真实零值仍显示 `0`。
8. 侧栏可用宽度不足 200 CSS px 时自动使用紧凑布局，恢复宽度后回到用户选择。Web `wide=false` 保留现有图标入口；Windows 桌面零宽折叠时随宿主隐藏，展开后恢复。
9. 用户选择的完整或紧凑状态写入浏览器本地偏好；只保存这一显示选择。自动窄栏降级不覆盖用户选择，存储不可用时使用内存状态。

布局继续位于官方 footer 槽位。维持该槽位内的整行显示，不移动宿主“设置”按钮，不增加常驻悬浮层，不承诺与参考插件完全相同的像素位置。

### 用量监控面板

原生设置导航名称统一为“用量监控”。面板包含三个页签。

```text
用量监控                            刷新
概览          供应商          设置

概览：今日用量、当前供应商、额度与余额卡片
供应商：已添加列表、重新扫描、添加与配置
设置：轮询间隔、保留期、侧栏显示
```

| 页签 | 默认内容 | 交互规则 |
| --- | --- | --- |
| 概览 | 今日用量、已添加数量、异常数量；已添加供应商的额度与余额卡片。 | 当前会话供应商优先，其余按稳定名称顺序。筛选只保留“全部”“需关注”；“需关注”包含取数失败和达到用户告警阈值的项目。卡片可以进入对应供应商配置。刷新历史默认收起。 |
| 供应商 | 已添加目录；每行显示名称、地域或凭据类别、状态、主指标、启用开关和“配置”。 | “重新扫描”仅发现配置，“刷新”仅查询额度。把“测试连接”移入供应商编辑页，减少行内按钮。可添加列表默认收起，扫描结果仍在当前页显示。 |
| 设置 | 轮询间隔、数据保留期、侧栏完整或紧凑选择。 | 轮询维持 10–3600 秒，保留期维持 1–90 天；保持现有默认值。宿主配置显式保存，本地显示偏好立即生效并标注“仅当前浏览器”。 |

概览卡片以供应商为单元，卡片内按周期限额、余额、报告费用或用量分组。沿用供应商 ID 作为身份：普通 Key 与 Management Key、组织 Admin Key、国内与国际条目不能因为显示名称相似而合并。同一个供应商可以同时拥有多个能力组。

内容区宽度达到 720 CSS px 时使用两列卡片；不足时一列。取消按供应商不断向右延伸的多栏布局，主页面不产生横向滚动。对话框宽度建议为 `min(960px, calc(100vw - 32px))`；原生设置页直接使用宿主内容列宽度。

颜色和背景继续使用宿主 `--dsw-*` 变量。金额和比例使用等宽数字；告警同时提供文字，不能只靠颜色区分。错误原因放在具体卡片或字段附近，详细响应按需展开，不把原始配置、调试字段或内部实现说明写入页面正文。

### 供应商编辑页

编辑页作为“供应商”页签内的子页。返回时恢复目录位置；从概览进入时，返回到原来的概览。结构固定为：

1. 标题区：供应商名称、地域、凭据类别、启用开关。
2. 当前数据预览：复用概览指标组件；说明这是已保存配置的最近查询结果。修改草稿不会把预览伪装成新配置的结果。
3. 凭据区：按现有 `meta.needs` 生成字段；已保存的密钥显示设置状态，输入留空保留旧值。
4. 高级选项：Base URL、警告阈值和临界阈值默认折叠；有关字段出错时自动展开并定位。
5. 操作区：测试连接、取消、保存。保存中禁用重复提交；失败保留输入并显示原因。

供应商草稿在当前面板内保留，切页不因背景刷新被覆盖。返回或关闭遇到未保存修改时，使用“继续编辑／放弃修改”的简短确认；保存中关闭仍沿用操作身份作废规则，重新打开后读取服务器实际状态，不自动重放保存。秘密字段只保留在编辑草稿生命周期内，不进入共享展示缓存或本地偏好。

### UI01 统一展示规则

改动位置：`lib/client.js` 的 `headlineOf`、`tightestOf`、`resetTextOf`、`EntryCard`；`lib/index.js` 的 `buildStatePayload`；`test/client.mjs` 和必要的状态响应测试。

- **UI01.1 指标选择。** 增加纯展示函数，例如 `selectPrimaryMetric(supplier)` 与 `buildEntryView(entry, supplier)`，返回类型、标签、值、单位、窗口、重置文案和告警色。只使用现有结构化字段，不从金额字符串反推额度。侧栏、概览、编辑预览共用它们。
- **UI01.2 状态显示。** 将“正常余额但无百分比”“尚未查询”“未启用”“查询失败”分开。`pct` 缺失不再自动使用错误色；余额不再显示“无限额概念（余额）”。保留 `0` 与缺失值的区别。
- **UI01.3 数据时间。** 在供应商状态响应中增加可选的 `lastSuccessAt`，直接来自现有 `scheduler.getState(id)`。失败尝试的时间不充当成功数据时间；旧响应没有该字段时省略时间，仍显示失败标记。`state.now` 只代表状态响应生成时间。

交付：旧界面先使用新的展示函数；后续布局批次无需再决定余额、百分比和错误态的语义。无需修改 `providers.js` 的查询与费用计算。

### UI02 共用面板和数据请求

改动位置：`lib/client.js` 的 `requestScheduler`、`useQuotaState`、`SettingsPanel.reload`、`DetailModal`、`SettingsSection`、`useDialog` 与 `apply`；`test/client-lifecycle.mjs`、`test/browser/shell.html`。

- **UI02.1 面板外壳。** 增加 `MonitorPanel`，统一“概览／供应商／设置”页签及供应商子页。原生槽位使用 `variant="page"`；侧栏使用 `variant="dialog"`。先接入现有详情和配置内容，保持本批可运行。
- **UI02.2 共享状态。** 将现有请求调度包装为一个随插件 `apply` 创建和销毁的展示控制器。控制器统一订阅当前会话和页面可见性；组件通过 `useSyncExternalStore` 订阅稳定快照。仅保留一套自动刷新循环，不在每个视图重新挂载现有 `useQuotaState`。
- **UI02.3 生命周期。** 第一个可见视图订阅时开始工作，最后一个视图离开或插件卸载时释放资源；隐藏文档暂停，恢复后立即获取一次。切会话作废旧请求。沿用现有 10 秒后台状态刷新、失败退避和手动刷新合并，不同时修改宿主供应商轮询周期。
- **UI02.4 编辑隔离。** 保存、重扫完成后通过控制器重新加载展示状态，不重新初始化已有编辑草稿。保留现有 `editorId`、操作序号和草稿修订检查，旧回调不能影响另一个编辑页。
- **UI02.5 页面与对话框。** `useDialog` 增加明确的启用条件。嵌入页面不创建遮罩、不声明第二个模态框、不截获宿主 Tab 与 Esc；对话框保留焦点限制、Esc 关闭和返回入口焦点。加载和失败状态同样遵循这一规则。

原生分区已经挂载时，侧栏入口通过插件自身控制器切换该分区的内部页签并聚焦标题；分区未挂载时，打开插件对话框。只根据自身组件的挂载状态协调，不能查找宿主菜单文本。若原生分区在插件对话框打开期间挂载，关闭插件对话框并接管当前内部页面和未提交草稿，避免出现两套可编辑界面。

交付：详情和配置拥有同一内容树与数据入口。函数可以先保留在现有 `lib/client.js` 闭包中，继续使用 `__ModuleLoader__` 的无构建加载方式，不引入打包器或新运行时依赖。

### 实施调整与边界

- 保留官方两个槽位和无构建加载；没有新增依赖、供应商查询方法、计费功能或用量数据迁移。
- 原生设置的滚动由宿主容器承载，因此返回位置通过组件自身最近的可滚动祖先保存，不依赖宿主菜单选择器。
- 在途保存锁跟随面板会话迁移；旧保存成功仍刷新共享状态，但旧编辑器没有回写资格。关闭后重新进入时，等待未结算写入及最新读取，避免用旧缓存创建草稿；不自动重放保存。
- 宿主 `settings.section` 没有可取消的外部导航接口。插件内返回、取消和关闭均提供未保存确认；宿主直接卸载原生分区时无法拦截，只能销毁草稿。该边界已同步 README 和桌面说明。
- 真实供应商查询与旧版实机检查不属于本轮必须执行的 A5 路径，无需人工操作即可完成本轮交付。若另行验收这两项，最少需要在隔离 profile 配置目标供应商凭据，或提供目标旧版宿主；结果须单独记录。
