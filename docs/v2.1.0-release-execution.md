# v2.1.0 发布执行记录

本轮把自 `fork-v2.0.5`（`e647b96`）以来未发布的两批改动一并发布：**DeepSeek 峰谷计费时段**（PR #1，`a9c6d53` / 合并 `04922e5`）与**常驻卡片重新排版**（本次）。两者叠加后是新增能力，因此按仓库约定递增次版本号到 **2.1.0**。

语义化依据：新增峰谷判定、今日用量时段拆分、节假日覆盖表与卡片新布局，均为新增／变更可见行为；无破坏性变更，存储格式仍为版本 1，可直接回读旧 `usage.json`。

## 1. 变更范围

| 能力 | 实现位置 | 说明 |
| --- | --- | --- |
| 峰谷判定 | `lib/season.js`（宿主为唯一权威） | 三条生效分界线、2026 年内置放假日表、`nextFlip` 只认真实状态变化 |
| 时段下发 | `lib/index.js` → `/state` 的 `season` | 客户端不复制规则，只消费结论并用 `flipAt` 本地递减 |
| 时刻列标注 | `lib/index.js` 刷新历史 `tier` | 按记录里的原始时刻回放当时的规则，不可归类显示 `—` |
| 今日用量拆分 | `lib/storage.js` `splitDayTokens` | 按小时桶纯读推导峰／谷／未知，仅 DeepSeek 挂 `seasonSplit` |
| 节假日覆盖表 | `lib/season.js` 校验 + 设置页文本框 | 写入侧拒绝坏日期，读取侧对坏配置静默回落内置表 |
| 卡片重排 | `lib/client.js` `FooterWidget` | 四行：plan 名／周窗口进度条／今日 + 重置／时段档位 |
| 进度条指标选择 | `lib/client.js` `weeklyEntryOf` / `selectBarMetric` | 周窗口优先 → 最紧有效窗口 → 文字回落，绝不画 0% 空条 |
| 量级格式化 | `lib/client.js` `fmtBig` | 统一 3 位有效数字，上限进位（`999.6K → 1.00M`） |
| 浮卡去重 | `lib/client.js` `UsagePopover` | 删除重复的计费时段块；缺次年告警移到设置页覆盖表旁 |

设计决策见 [ADR 0001：峰谷时段判定归宿主](adr/0001-peak-valley-season-host-authority.md)。

## 6. 验证边界（**未执行项**）

- **未跑真实宿主验收**：`npm run test:desktop`、`scripts/verify-web.mjs`、`npm run test:lifecycle`
  均需 Windows 桌面端可执行路径，本轮未执行，因此「真实 Desktop／Web 安装、原生设置入口、侧栏收起
  恢复」仍沿用 v2.0.4 的结论。
- **未接触真实计费账户**：峰谷判定与用量拆分只用内置日历表与本地小时桶验证，未用真实 DeepSeek 账单
  比对金额；本轮**不引入价目表**，因此不计算金额，也不存在与账单对账的口径。
- **卡片周窗口靠窗口名识别**：窗口标签是 `lib/providers.js` 生成的中文常量（`周用量`／`周窗口 · GOAT`／
  `Token 用量（周）`）。若某供应商改标签，卡片回落到「最紧的有效窗口」并显示该窗口真名——数字不会错，
  只是可能不是周窗口；`data-qm-window="other"` 让这种回落可被测试观察到。
- **上游同步未做**：本轮只推送 fork 远端（`origin` = `cup113/dsh-usage-monitor`），不推上游
  `shxtmaker/dsh-token-quota`，不创建 GitHub Release。
- **峰谷规则变更的滞后**：客户端不复制规则，宿主换规则后界面最多滞后一个轮询周期（10s）才更新档位。
- **产物侧的浏览器套件未实跑**：受限沙箱拒绝 Playwright 派生浏览器进程（`spawn EPERM`），因此 27 项
  浏览器用例是在仓库工作区跑的；产物侧改用 `lib/` 与 `test/` 逐字节同一性证明（见第 5 节），
  而非重跑一遍。
