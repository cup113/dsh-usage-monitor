# 0001 峰谷时段由宿主判定，今日峰谷拆分从「供应商 × 本地小时」桶推导

状态：已采纳（v2.1.0 起）

## 背景

DeepSeek 按账户的峰谷时段计价：北京时间周一至周五（不含中国法定节假日）09:00–12:00、14:00–18:00 为高峰时段，其余时段（夜间、周末、法定节假日全天）为空闲时段，单价是高峰的一半。官方价格页脚注 (2) 是唯一权威口径，且规则本身有过三次生效分界（2026-08-17 峰谷实施、2026-08-23 起周末全天谷价、2026-09-19 起节假日全天谷价）。

上游参考实现 `dsh-tide-badge` 用 `lib/build.mjs` 把 `season.mjs` **内联**进客户端产物，因此宿主与浏览器共享同一份规则源码，不存在两份实现漂移的问题。

本插件的约束不同：

- `lib/client.js` 是**手写、无构建步骤**的文件（`exports["./client"]` 直接指向它，由 harness 的 `dsh-client-modules` 原样下发并注入浏览器）。没有构建期，也就没有"内联同一份源码"这条路。
- 节假日表需要年度维护：国务院每年 11 月发布次年安排，内置表只能覆盖已公布年份。缺次年不会报错，只会把工作日假期**静默**当成峰价（多算钱）。
- 今日 Token 用量已经按「供应商 × 本地小时」保存（`lib/storage.js`，`usage.json` 版本 1），值是裸整数。

## 决策

1. **时段判定与节假日表只存在于宿主**（`lib/season.js`），客户端消费 `/state` 下发的结论（peak / kind / valleyReason / flipAt / beijing / warning），只用 `flipAt` 本地递减倒计时，**不复制规则**。
2. **今日峰谷拆分纯读推导**，不新增存储结构、不改 `usage.json` 版本：逐小时用桶 key 算出该桶的本地时刻，再按北京规则归入峰/谷/未知。
3. **节假日覆盖表**作为根级 volatile 配置字段 `holidays`，读取侧静默净化坏数据，写入侧（`/settings`）显式拒绝。

## 理由

- **不复制规则**：两份实现会漂移，而漂移的后果是静默算错钱。代价是客户端只知道"现在是什么"，切换后会滞后最多一个 `/state` 轮询周期（10s）；对一个被动展示的侧栏来说可接受，换取的是官方改规则时只改一处。
- **从小时桶推导可行**：峰谷的全部边界都落在整点（09:00/12:00/14:00/18:00），北京又是整小时偏移，因此一个本地小时桶换算到北京时间后必然整体落在同一时段内 —— 小时粒度不会切错时段。这条性质是"不建新存储"的前提，一旦官方把窗口边缘改到半点就不成立（届时需要改存储）。
- **本地日口径保持不变**：拆分沿用既有的「宿主本地日」求和口径（逐小时归属），因此不需要改变用户已经理解的"今日用量"含义，也不影响非 +08:00 时区的现有数据。
- **拒绝而不是净化（写入侧）**：`settings.update` 只做 JSON 形状校验、不按 schemastery 校验，坏日期会原样落盘；用户以为"粘贴成功"却被静默丢弃，比报错更糟。
- **净化而不是抛错（读取侧）**：配置可以被手工改坏。判定逻辑因为一个坏字段整块消失，比少认一个假日更糟，所以读取侧回落到内置表。

## 后果

- 新增年度维护动作：国务院发布次年安排后补 `lib/season.js` 的内置节假日表 `HOLIDAY_VALLEY`。缺覆盖会在启动日志与界面上同时点名，并可用覆盖表即时修正。
- 侧栏时段行的档位与倒计时以 `/state` 轮询为界，切换后最多滞后一个轮询周期；未知时刻（`flipAt` 为 null 或占位）一律不显示倒计时，不推算切换时间。
- 峰谷拆分只对 DeepSeek 给出（`seasonSplit` 对其他供应商恒为 null），避免把 DeepSeek 专属计价规则解释成全供应商通用折扣。

## 被否决的替代方案

- **客户端内联规则（照搬 tide-badge）**：需要引入构建步骤，与"手写无构建客户端"这一现状冲突；或手工维护两份规则，漂移风险不可接受。
- **给存储加时段标签（`{tokens, tier}`，版本 2）**：需要迁移旧文件、改写入路径与修剪逻辑，换来的只是省掉一次可证明正确的换算；而且坡度收益为零（边界都在整点）。
- **把时段判定做成新的轮询路由**：`/state` 已经每 10s 轮询，新增路由只是多一次请求与一处 TTL，没有任何正确性收益。
