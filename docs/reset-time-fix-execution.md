# v2.0.4 供应商重置时间修复

## 故障复现与根因

用户截图显示 Command Code 的 5h 和周窗口为“1月1日 重置”，OpenCode Go 的窗口倒计时正确。通过供应商查询入口注入 `resetAt: 0` 的响应，稳定复现该文案。首个回归命令 `node --test test/reset-times.mjs` 在修复前失败，实际值为 `1月1日 重置`，期望值为 `—`；原始输出保存在本地 `.scratch/reset-times-red.log`。

数据层的 `parseDate(0)` 产生了 1970 年 1 月 1 日的 Date 对象。`resetAtMs()` 将其判为未知，但 `formatReset()` 仍将其格式化为日历日期。前端拿不到有效倒计时后回退使用错误的日期文案，因此呈现截图中的异常。数字串 `"0"` 还可能被 JavaScript 日期解析解释为 2000 年 1 月。

补充检查发现，数据层和客户端使用的 `1e9` 毫秒阈值与注释所写的“2001-09 之后”不一致；正确数量级为 `1e12`。旧阈值会接纳误传入毫秒字段的秒级值，生成 1970 年日期或错误的“即将重置”。

## 修复

- 日期解析、日期文案及原始时刻共用有效性判断，拒绝零值、无效日期和小于 `1e12` 的毫秒字段值。
- 数字串按毫秒契约解析，不交给 JavaScript 进行短数字的日历猜测。
- 缺失或无效的窗口时刻显示 `—`；Command Code 同时保留“未提供重置时刻”说明。订阅周期缺失时保留“周期结束未公布”。
- 客户端倒计时使用同一数量级下限，避免错误单位被显示为到期。
- 有效毫秒、毫秒数字串和带时区日期保持原始精度，不为未知时刻推算下一次重置时间，也不将订阅周期起点当作终点。

`test/reset-times.mjs` 覆盖 Command Code 的 5h、周和月窗口占位值，以及 OpenCode Go 的 5h、周和月有效时刻。浏览器回归直接调用真实供应商解析函数处理固定响应，再将结果送入真实客户端，验证未知重置显示 `—`、有效月窗口及 OpenCode 倒计时保留，详情不出现“1月1日”或 `NaN`。
